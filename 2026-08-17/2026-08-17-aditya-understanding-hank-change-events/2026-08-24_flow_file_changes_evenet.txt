0. THE TWO INDEPENDENT GATES -- BOTH MUST PASS
=============================================================================
An audited write emits a change event only if it clears BOTH of these. Every
flow write site today fails at least one, and most fail both. Fixing one
without the other produces nothing, which is why this has to be done as a pair.

GATE 1 -- claims()          hank/db/audit.go:33-41
    func claims(scope *gorm.Scope) (*token.AuthClaims, context.Context, bool) {
        dbContext, _ := scope.DB().Get("context")
        if dbContext == nil {
            return nil, nil, false          // <-- gate closes here
        }
        ...
    }
    "context" is set ONLY by hdb.BeginTxDB (hank/db/audit.go:230-234, via
    tx.InstantSet("context", ctx)). A bare `db *gorm.DB` handle never has it.
    The hook then returns at hank/db/audit.go:171 (AfterUpdate) /
    :152 (AfterCreate) / :207 (AfterDelete) with `if !parsed { return nil }`
    BEFORE publishChangeEvent is ever reached.

GATE 2 -- ObjectID          hank/db/change_events.go:270-276
    AuditLog.ObjectID comes from getObjectDetails(scope.Value)
    (hank/db/audit.go:59 -> :250-262), which JSON-marshals scope.Value and
    reads the key "ID". If it is empty the event is skipped with
    Warn("change event skipped: empty ObjectID").

0.1 WHEN IS scope.Value POPULATED? -- the precise rule
    This is subtler than "don't pass an empty struct", and getting it wrong is
    why the DataImportJob path works while the flow path does not.

    For UPDATES gorm MUTATES scope.Value before the hook runs.
    Callback order, gorm v1.9.11 callback_update.go:11-20:
        gorm:assign_updating_attributes   <- :12, runs FIRST
        gorm:begin_transaction
        gorm:before_update
        gorm:update
        gorm:after_update                 <- :18, the audit hook
        gorm:commit_or_rollback_transaction
    assignUpdatingAttributesCallback -> scope.updatedAttrsWithValues(attrs),
    which at gorm scope.go:919 calls field.Set(value) -- writing the update
    payload's fields ONTO the model instance. convertInterfaceToMap at
    gorm scope.go:897 includes a field only `if !field.IsBlank`.

    For DELETES there is NO such step. gorm callback_delete.go:9-15 registers
    only begin_transaction, before_delete, delete, after_delete,
    commit_or_rollback. Nothing ever populates scope.Value.

    RESULTING RULE:

      CALL SHAPE                                  ObjectID   EVENT
      ------------------------------------------  ---------  --------
      Updates(<struct with non-blank ID>)         merged in  FIRES
      Updates(map{...}) with no "ID" key          blank      skipped
      Update("col", val)                          blank      skipped
      Delete(&models.X{})                         blank      skipped
      Delete(x) where x.ID is set                 present    FIRES
      Create(x)                                   set by
                                                  BeforeCreate  FIRES

    THIS IS WHY forebitt WORKS:
        forebitt: tx.Model(&models.DataImportJob{}).Updates(*job)
        *job carries a non-blank ID, so gorm merges it into the empty struct
        and the hook sees it. The empty literal in Model() is irrelevant --
        what matters is what Updates() carries.

    AND WHY unhygienix FLOWS DO NOT:
        db.Model(&models.CleanRoomFlowRun{}).Scopes(IDScope(id)).Update("job_status", status)
        The update map is {"job_status": ...}. No ID anywhere. scope.Value.ID
        stays "". Skipped.

1. CHANGE LIST -- unhygienix/db/flows.go
=============================================================================
models.CleanRoomFlowRun embeds UUID (unhygienix/models/flows.go:172), and
models.UUID is `struct { ID string }` (unhygienix/models/audit.go:15-17), so
the fix is to construct the model WITH its id instead of empty.

Note: a non-zero primary key makes gorm add its own `id = ?` predicate
(scope.whereSQL / PrimaryKeyZero), so IDScope becomes redundant. Keeping it is
harmless -- same column, same value -- and is the lower-risk edit. Shown below
with IDScope retained.

3. WHAT CANNOT BE FIXED THIS WAY -- flow NODE failure
=============================================================================
  unhygienix/models/flows.go:255-261
      type FlowNode struct {
          TimeAudit
          FlowID           string `gorm:"primaryKey;..."`
          NodeID           string `gorm:"primaryKey;..."`
          ReferenceVersion int32
          FlowVersion      int32
      }

  TWO blockers, and the second is fatal to the obvious fix:

  (a) No hdb.Audit embed, so no hooks fire at all. Adding it means a migration
      for four columns (audit_created_at, audit_updated_at,
      audit_created_by_user, audit_updated_by_user).

  (b) NO `ID` FIELD. The primary key is composite (FlowID, NodeID,
      FlowVersion). getObjectDetails (hank/db/audit.go:250-262) only ever looks
      for values["ID"], so even WITH hdb.Audit added and the migration run,
      every event would still be skipped at GATE 2. Adding Audit is necessary
      but not sufficient.

  (c) More decisively: FlowNode is a STRUCTURAL / versioning record. A node
      failing at runtime does not write a FlowNode row at all, so there is
      nothing to hook even if (a) and (b) were solved.

  WHERE NODE EXECUTION STATE ACTUALLY LIVES:
      pegleg's Temporal workflow triggers a node and then POLLS unhygienix:
        pegleg/pegleg-server/src/main/java/com/habu/pegleg/flow/activity/HabuFlowActivities.java
            @ActivityInterface: triggerNode / triggerEdge / triggerCompletion / markFlowPaused
        .../flow/activity/HabuFlowActivitiesImpl.java:22-25   holds UnhygienixClient
        .../flow/activity/HabuFlowActivitiesImpl.java:33      unhygienixClient.triggerNode(...)
        .../flow/activity/HabuFlowActivitiesImpl.java:96      unhygienixClient.getActivityStatus(...)
      Pegleg orchestrates and polls; unhygienix owns the row. EMIT FROM
      UNHYGIENIX, NOT PEGLEG -- emitting from pegleg would duplicate events and
      put the source on the orchestrator rather than the system of record.

  RECOMMENDED APPROACH FOR NODE FAILURE:
      Emit at the CleanRoomQuestionRun level. A flow node that is a question
      node resolves to a clean room question run, and a failure there is the
      real, already-persisted event. Before committing to this, run the same
      two-gate audit on CleanRoomQuestionRun:
        1. does it embed hdb.Audit?
        2. do its status write sites pass ctx and carry the ID?
      Expect the same empty-struct pattern; the fix would be identical to 1.1.

7. FINDING THE REST -- the two-gate sweep
=============================================================================
  GATE 2 candidates (empty struct literals):
      grep -rn "Delete(&models\.\|Delete(models\.\|Model(&models\." unhygienix/db/ \
        | grep -v _test.go
      Any hit where the literal is EMPTY and the id comes only from a Scope is
      a silently-skipped event -- unless it is a read (Find/Pluck/First/Count).

  GATE 1 candidates (no ctx / no BeginTxDB):
      grep -rn "^func .*(db \*gorm.DB" unhygienix/db/ | grep -v _test.go
      Any write function whose signature takes a bare `db *gorm.DB` and no ctx
      cannot pass claims(), regardless of ObjectID.
