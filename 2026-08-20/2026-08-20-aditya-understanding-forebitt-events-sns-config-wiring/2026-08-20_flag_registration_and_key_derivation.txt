The prefix grows by one element per hop, purely through `append`:

    AddEvents  prefix = ["events"]
    AddSNS     prefix = ["events","sns"]
    AddAWS     prefix = ["events","sns","aws"]


3. MakePrefixKey is a string join — nothing more
------------------------------------------------
hank/cmd/config/parameters.go:56-62

    func MakePrefixKey(key string, prefix []string) string {
        if len(prefix) == 0 {
            return key
        }
        return strings.Join(prefix, ".") + "." + key
    }

So `MakePrefixKey("accesskey", ["events","sns","aws"])` == "events.sns.aws.accesskey".

The leaf names come from consts at hank/aws/config.go:20-29:

    AccessKey        = "accesskey"
    SecretKey        = "secretkey"
    SessionToken     = "sessionToken"      <- note the camelCase; viper lowercases it later
    RoleArn          = "rolearn"
    Region           = "region"
    Endpoint         = "endpoint"
    S3ForcePathStyle = "s3forcepathstyle"
    MaxFileSize      = "maxfilesize"

and Topic = "topic" at services/events/config.go:10.

5. Where the key strings physically live
----------------------------------------
Two in-memory maps. Nothing on disk.

(a) The pflag FlagSet.
    `flags.String(name, "", usage)` allocates a *string holding "" and stores a
    *pflag.Flag{Name: "events.sns.aws.accesskey", DefValue: "", Value: ...} in
    the FlagSet's internal `formal` map. The dots are not special to pflag — this
    is just a flag whose name happens to contain dots. It could be passed on the
    command line as `--events.sns.aws.accesskey=xyz`.

(b) viper's `pflags` map, after binding (see the env-binding document):
    viper@v1.12.0/viper.go:1172

        v.pflags[strings.ToLower(key)] = flag

    viper stores the key name and a handle to the flag. It stores NO value.

The values themselves live in `os.Environ()`, loaded from .env by godotenv.
viper never copies them in; it does a live os.LookupEnv on every read.


6. Why registration matters even though the flags are never typed on the CLI
-----------------------------------------------------------------------------
Registration is what makes a key *exist* for viper. viper.Unmarshal decodes
`AllSettings()`, which iterates `AllKeys()` (viper.go:1940-1950):

    m = v.flattenAndMergeMap(m, castMapStringToMapInterface(v.aliases), "")
    m = v.flattenAndMergeMap(m, v.override, "")
    m = v.mergeFlatMap(m, castMapFlagToMapInterface(v.pflags))       <- our keys
    m = v.mergeFlatMap(m, castMapStringSliceToMapInterface(v.env))   <- BindEnv only
    m = v.flattenAndMergeMap(m, v.config, "")
    m = v.flattenAndMergeMap(m, v.kvstore, "")
    m = v.flattenAndMergeMap(m, v.defaults, "")

`v.env` is populated only by explicit `BindEnv` calls (viper.go:1192).
`AutomaticEnv` sets a single boolean (viper.go:1403-1404) and enumerates nothing.

CONSEQUENCE, and this is the reusable rule:

    An environment variable whose key was never registered as a flag
    (or default, or config-file entry, or BindEnv) is INVISIBLE to
    viper.Unmarshal. It will not error. It will silently do nothing.

This is exactly why two of the seven FOREBITT_EVENTS_* vars in .env are dead.
