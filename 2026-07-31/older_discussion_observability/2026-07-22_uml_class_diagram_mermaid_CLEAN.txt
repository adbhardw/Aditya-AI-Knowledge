CORRECTION 2026-07-22 (verified against the real scaffold, orinix repo):
  - The Map<String, DeliveryChannel> aggregation is on CallbackDeliveryWorker
    (CallbackDeliveryWorker.java:34), NOT DeliveryDispatcher. The earlier
    version of this file wrongly put it on DeliveryDispatcher — corrected above.
  - DeliveryDispatcher holds only CallbackRegistrationRepository +
    QueueMessagingTemplate + ObjectMapper(Jackson). It does NOT reference
    DeliveryChannel and does NOT reference CallbackDeliveryWorker directly —
    the two are decoupled through the SQS queue sqs-habu-delivery-xmi
    (Dispatcher convertAndSend -> queue; Worker @SqsListener <- queue).
  - CallbackRegistrationEntity added: it's the DB row that stores WHICH
    delivery mechanism a consumer (e.g. XMI) registered — delivery_type
    (WEBHOOK|PUBSUB) + delivery_config (url/topic). The worker reads
    registration.getDeliveryType() to pick the channel from the Map.
  - ObjectEventMapper REMOVED from this diagram: not present in this
    checkout of the orinix repo (the Q8 schema-drift work referenced one,
    which may live in a different checkout — re-verify before drawing it).

HOW THE ARROWS READ (so you can explain it live)
================================================================================

  <|..  hollow triangle, dashed  = "implements/realizes an interface"
        WebhookDeliveryChannel and PubSubDeliveryChannel each realize
        DeliveryChannel. THIS is the Strategy pattern — the one line
        the Miro version dropped.

  o-->  open diamond  = "aggregates" — DeliveryDispatcher holds a Map
        of many DeliveryChannel (Spring auto-collects each @Component
        by name; no factory class).

  ..>   dashed arrow  = "uses/depends on" — the worker uses a channel
        to deliver and the mapper to build the payload; ReplayService
        reuses the worker's deliverToRegistration method.

Caption for the slide:
  "Adding a new delivery mechanism (e.g. Azure Event Grid) = one new
  class implementing DeliveryChannel. No change to the dispatcher, the
  worker, or any existing channel. Open/closed principle in practice."
