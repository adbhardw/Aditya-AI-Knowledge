The key concept:
Promtail doesn't send one log at a time. It works like this:

Tails files — watches /var/log/pods/*/ for new lines (like tail -f)
Batches logs — collects multiple log lines (default: up to 1MB or 10s, whichever comes first)
Attaches labels to the entire stream, not to each individual log line
Pushes batch to Loki via HTTP POST
Where cluster=eks-admin-prod comes from:
In the Promtail Helm values or config:

# Helm values (typical)
config:
  clients:
    - url: https://logs-prod-us-central1.grafana.net/loki/api/v1/push
  snippets:
    extraRelabelConfigs: []

extraArgs:
  client.external-labels: "cluster=eks-admin-prod"

Or in the raw Promtail config:

clients:
  - url: https://logs-prod.grafana.net/loki/api/v1/push
    external_labels:
      cluster: eks-admin-prod    # ← This is added to ALL logs from this Promtail instance

The actual commands to deploy it:
# 1. Add the Grafana Helm repo (one time)
helm repo add grafana https://grafana.github.io/helm-charts
helm repo update

# 2. Create your values.yaml
cat <<EOF > promtail-values.yaml
config:
  clients:
    - url: https://logs-prod-us-central1.grafana.net/loki/api/v1/push
      basic_auth:
        username: <LOKI_USER_ID>
        password: <GRAFANA_CLOUD_API_KEY>
      external_labels:
        cluster: eks-admin-prod

extraArgs:
  client.external-labels: "cluster=eks-admin-prod"
EOF

# 3. Install (or upgrade) on your cluster
helm upgrade --install promtail grafana/promtail \
  --namespace monitoring \
  --create-namespace \
  -f promtail-values.yaml

# 4. Verify it's running on all nodes
kubectl get pods -n monitoring -l app.kubernetes.io/name=promtail -o wide

To verify the config after deployment:
# See the rendered config with cluster label
kubectl get cm -n monitoring promtail -o yaml | grep -A5 "external_labels\|cluster"

Key point:
You deploy this once per cluster. Each cluster gets its own Promtail install with its own cluster=<name> label. That's how Loki knows which cluster a log came from — it's hardcoded in the Promtail config for that cluster, just like
clusterName:
prod
 is hardcoded in the Datadog Agent Helm values for that same cluster.
